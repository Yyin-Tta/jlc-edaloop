# jlc-edaloop 产品分析与布局卡点开发路线

> 分析日期：2026-09-02  
> 适用范围：v2 原理图闭环、当前 v0.6.x/v0.7.0 过渡状态及 v3 远期规划。  
> 证据口径：仓库文档、代码、评测产物和真机问题记录分开看。离线单元测试、注入式 checker 评测、固定金标和真实 EasyEDA 运行，不可混算为同一种成功率。

## 1.项目核心价值与机会点

**结论先行：项目值得推进，但真实产品应是“受控电路块域内的原理图草案生成、机械预检与审计辅助工具”，不是“从脑洞到可生产电路的自主设计 Agent”。**

真实机会集中在低速数字、电源、USB、UART、RS-485、I2C、SPI、MCU 最小系统等重复性很高的板级设计。用户并非完全不会画图，而是反复承担以下低价值工作：

- 拼接经过验证的参考电路、电源和接口块；
- 核对型号、封装、引脚、C 号和 BOM；
- 发现低级错连、漏接、重复标记和页面布局问题；
- 给评审、变更和交付留可回放证据。

| 机会 | 真实程度 | 当前限制 |
|---|---|---|
| 受控电路块自动拼装 | 高 | 依赖块库覆盖，不能泛化到任意拓扑 |
| C 号 BOM 与网表输出 | 中高 | 库、价格、库存、MOQ 和 API 会变化 |
| 开源、本地部署 | 潜力高 | 当前默认仍依赖远程 LLM/Embedding，安装复杂 |
| 研究所/军工使用 | 长期机会 | 当前没有气隙部署、权限、认证和工具链准入证据 |
| “脑洞到订单” | 低 | PCB、报价、下单只是编排或草稿，不能视为无人值守闭环 |

仓库已有 97 个块、结构化 `DesignIR/BlockPlan/Finding`、typed actions、审计和 replay，说明它已经超过演示玩具。README 中的 recall@8 93%至95%、旧金标 22/22、单个 req-27 全链路通过，证明了受控样本上的工程能力；但这些数字不能解释为生产成功率。当前可见的 hard 回归记录只有 3/6 PASS，P5-1 真实 datasheet 批次也只有 5/10 入库，案例库只有少量种子案例。

更合理的近期承诺是：

> 对已支持的电路块和器件，在 EasyEDA Pro 中生成可编辑的原理图草案，完成有限的引脚、网络、电气和几何检查，并输出带出处、未知项和人工签核点的交付包。

## 2.致命风险与现实短板（不客套，直接点问题）

最危险的问题不是 LLM 偶尔答错，而是系统会把“尚未证明”的结果标成 PASS。

| 风险 | 已有证据 | 产品后果 |
|---|---|---|
| **门禁假通过** | req-08 曾出现同一 pin、同一网络挂多个标记，round gate 仍为 pass；req-07 多个布局缺陷由用户目检发现 | 用户把结构检查误解为工程正确性，可能形成责任事故 |
| **RAG 冷启动和数据错误** | 97 个块、案例很少；真实 10 份 PDF 仅 5 份入库，族级、多封装、多表格失败；曾发生 JOIN 和参数误配 | 检索命中不等于型号、引脚或参数正确 |
| **迭代震荡** | 最多 5 轮、同码 2 轮 HALT；真实出现侧位反复、修复器累积标记和移动后错网 | 既可能烧掉模型额度，也可能误停或制造新错 |
| **外部 EDA 单点故障** | 连接器负载后 NO_CONNECTOR 数分钟不自愈；云端器件可稳定卡死；无 undo 只能删除和重放 | 无法承诺无人值守、CI 或长任务可靠性 |
| **状态与交付不一致** | block-apply 曾报告 rollback verified 但器件残留；页数累积曾导致 netlist 导出失败 | 可能出现 gate 通过但交付物缺失或工程被污染 |
| **本地部署被过度宣传** | 默认 LLM/Embedding/Reranker 走远程兼容 API；无 key 直接失败；没有开箱即用的本地模型包 | “企业数据不出域”目前不成立，用户还要承担 GPU、模型和更新维护 |
| **案例自进化污染** | 回写仅 PASS、非 eval、origin/hash 护栏；缺人工审核、质量分、负例、衰减和租户隔离 | 一个错误 PASS 可能被反复检索，形成错误正反馈 |

### RAG 与 datasheet

当前 SQLite + FTS + dense + rerank 的结构对小库合理，但电路拓扑不是普通文本相似度。端口方向、供电域、封装变体、阻容约束和网络连接必须做结构化过滤，不能只靠向量分数。recall@8 只说明金标块出现在候选中，不说明 planner 选对了，也不说明网表可用。

引脚表提取可以作为窄范围强校验；参考设计图、多封装族表、去耦和上拉要求必须分级。去耦要求的“是否提全”没有机械判据，只能带页码和原文进入弱门禁及人工确认。库符号本身也可能错，LCSC 不能无条件当作真值。

### 机械门禁的现实边界

`sch gate`、连通性、pin diff、开短路、部分电压/电流和本体相交检查，能证明的是**已编码的形式约束**。它不能证明：

- 功能和时序真的符合需求；
- 模拟环路稳定、增益、带宽和补偿正确；
- 高速信号完整性、电源完整性、EMC、热和安规成立；
- 去耦、保护、降额和制造工艺要求完备；
- 云端库器件数据、封装和替代料没有错误。

当前目检协议已经承认翼擦、文字可读、框外墨迹、并轨形态等仍有人工部分。因而产品文案中的“机械校验后可交付”是危险的伪命题，应改为“通过已定义检查，仍需工程签核”。

### 迭代循环

固定 N 轮只是止损，不是收敛证明。需要把设计错误、布局错误、平台错误、数据错误分开计数；对每轮保存工程快照、动作 diff 和后置条件；先做白名单确定性修复，再决定是否重规划。A 类 finding 变成 B 类 finding，或者指标没有改善，也应立即 HALT 并升级人工，而不是继续重试。

### API、部署和业务

系统依赖 Windows、EasyEDA Pro 前台窗口、扩展连接器、daemon、精确版本的 easyeda-agent 以及云端器件库。官方 `eda.*` API 和下单接口没有稳定公开契约，版本、窗口、designator、页签、网络回读和库数据都可能静默变化。长任务还会受到连接器假死、GUI 重绘和模型限流影响。

业务上还存在数据出域、datasheet/LCSC 再分发许可、客户电路 IP、AI 责任、军工供应链合规和长期维护成本。开源不等于免维护，也不等于客户愿意承担安装和验收风险。

## 3.用户与需求真实性校验

| 用户 | 真实痛点 | 当前能满足 | 当前不能承诺 |
|---|---|---|---|
| 爱好者、学生 | 想快速得到常见模块、理解连接和看到结果 | 常见 MCU、USB、电源、LED 模板；网表、BOM 和告警可用于学习 | 低门槛安装、任意电路、无需复核；当前 Windows、Pro、daemon、密钥配置过重 |
| 普通硬件工程师、中小团队 | 重复块、C 号选型、BOM、评审留痕、减少低级连线错误 | 受支持块库内的数字/电源/接口草案、确定性编译、审计和基础门禁 | 高速、模拟、射频、时序、EMC、热设计和安全关键电路；仍需工程师复核 |
| 研究所、军工 | 气隙运行、权限、审计、可复验、批准器件、长期支持 | 非敏感原型阶段可做技术预研 | 当前云端模型、专有 EasyEDA/连接器依赖、无 RBAC/认证/供应链和签核体系，不能进入涉密生产 |

最现实的首批用户是使用嘉立创 EDA 的中小硬件团队、方案公司和个人工程师。他们能容忍人工确认，也最直接感受到重复设计和 C 号 BOM 的收益。爱好者适合做传播和反馈，不适合作为可靠性证明；军工客户适合验证需求方向，不适合在当前阶段作为销售承诺对象。

| 理想说法 | 现阶段事实 |
|---|---|
| 任意“脑洞”直接生成 | 主要接受结构化需求，歧义仍需人工回答 |
| 任意 datasheet 驱动设计 | 文字型 PDF 有限支持，扫描件和多封装场景会拒收 |
| 机械校验后即可交付 | 只能证明已编码的结构和局部电气规则 |
| 案例越用越强 | 生产级回写和后续消费尚未形成充分 run 级证据 |
| 全本地、数据不出域 | 当前默认仍是远程 LLM/Embedding |
| 自动下单 | 最多生成报价和订单草稿，支付仍须人工 |

## 4.产品&架构方案评估（v2重点，v3做远期评估）

### v2 五段闭环

| 环节 | 可行性 | 必须补的能力 |
|---|---|---|
| M1 意图解析 | 中高 | 统一需求、BOM、PDF 和对话输入；保存约束出处、冲突和确认历史；不能静默猜测 |
| M2 RAG | 中 | 小库可用；要有型号/端口/电气硬过滤、版本和新鲜度、置信度、拒答机制 |
| M3 两段生成 | 高但受限 | BlockPlan + typed actions 是正确核心；自由拓扑只保留白名单模式，关键网络用规则编译而非 LLM 自由发挥 |
| M4 校验 | 结构高、功能低 | pin/net/开短路/重复载体/已知电压电流/DRC/几何可强；未知必须阻断或人工签核 |
| M5 迭代 | 中 | 事务快照、最小变更、状态回读、错误分类、预算和人工停点；critic 只能当建议，不是安全证明 |
| M6 入库 | 中低 | 先做文字 PDF 的引脚和数值表，参考图和去耦保留人工审核 |
| 交付 | 可做 | BOM、网表、审计、出处和未知项齐全；任一关键文件缺失必须 fail-closed |

M8/M9 目前本质上是对 easyeda-agent 的 PCB 编排和报价草稿，不是自主 PCB 引擎或稳定下单平台。它们可以保留为 showcase，但不应成为 v1 的可靠性 SLA。

### v3 需要裁剪

多轮需求细化可以保留为独立的输入模块；PCB 只先支持低速、两层、人工确认的编排；报价只输出带时间戳的草稿。任意模拟综合、高速布线、全局成本最优、自动替代料和自动下单都应远期处理。支付永远不自动化。

## 5.差异化真伪辨析：四支柱哪些是硬核壁垒，哪些存在现实短板

| 支柱 | 判断 | 现实情况 |
|---|---|---|
| 开源 + 本地部署 | 潜在优势，不是现成壁垒 | 开源带来信任、二开和获客；当前没有开箱即用的全离线模型、权限和升级方案 |
| LCSC/C 号原生 | 强集成便利，弱独占壁垒 | 对中国打样很有价值，但 EasyEDA 官方和竞品都能复制；价格、库存、MOQ、C99xx 和 API 不稳定 |
| 机械复验闭环 | 最强潜在差异，但只是风险缩减器 | 真正可守的是缺陷数据、回放、覆盖集和公开基准，不是“调用了 gate” |
| 案例自进化 | 当前接近包装性卖点 | 案例少、生产飞轮未充分转动，缺审核、负例、版本、回滚、脱敏和租户隔离 |

竞品应按公开能力而非宣传口号比较：

| 对象 | 优势 | 本项目相对位置 |
|---|---|---|
| easyeda-agent | API 编排、typed actions、块库和门禁经验 | 主要是下游依赖，应作为互补而非假想替代 |
| EasyEDA 官方扩展/助手 | 平台权限、分发、原生 UX 和供应链入口 | 最大生态替代风险 |
| easyeda-copilot | 自然语言、器件搜索、SPICE 方向 | 本项目在审计、受控 RAG 和门禁编排上有差异 |
| Flux.ai | 闭源但产品整合、知识库、UX 和自纠错更完整 | 本项目的开源、私有部署和中国供应链是局部差异，不是全面性优势 |
| Quilter、Altium、Cadence 等 | PCB 物理、企业流程和支持体系 | 不在同一成熟度层级，不能用 demo 指标对比 |
| KiCad、Jitx、脚本化工具 | 离线、可控、生态成熟 | 本项目的 EasyEDA/LCSC 集成是便利，不是不可替代性 |

## 6.MVP落地与版本划分建议：核心必做/延后/直接搁置

### 核心必做

1. 冻结支持矩阵：低压数字、电源、USB/UART/RS-485/I2C/SPI，限制器件数量和复杂度；把模拟、高速、射频和安全关键电路列为禁区。
2. 建立 20 至 30 个人工审核块：pinout、封装、C 号、电气范围、来源、版本和真机 smoke 证据齐全。
3. 固化 `DesignIR → BlockPlan → typed actions`，增加 schema、模型、提示词和块库版本记录。
4. 做 pin/net/开短路/重复载体/已知电压电流/DRC/本体相交/出带硬门禁；未知状态进入人工队列。
5. 每轮保留快照、动作 diff、幂等清理和最终回读；交付物缺失即失败。
6. 只允许白名单确定性布局修复；finding 不变或指标不改善就 HALT。
7. 固定交付 BOM、网表、审计、检查清单和 provenance，C 号、库存、价格带时间戳。
8. 提供 preflight、无 EasyEDA dry-run、真实 EasyEDA smoke、replay 和清晰的责任声明。
9. 分开统计 Fake、真机、外部用户和生产数据，不再用 pytest 全绿代表平台可用。

### 可以后续迭代

本地模型打包、文字 PDF 半自动入库、更多人工审核块、有限 freeform、多页排版、价格提示、Web UI、SPICE 子集、人工批准后的案例推荐和小规模低速 PCB 编排。

### v3 远期再考虑

复杂 PCB、仿真辅助、模拟优化、制造文件和报价整合。下单最多做到人工确认前的草稿，支付永远不自动化。

### 直接搁置

无审核案例自动回写、任意拓扑自由生成、扫描件万能解析、全局成本最优、无人值守“脑洞到制造”、军工生产级承诺。

### 当前布局卡点专项开发路线

当前问题不是简单把 spacing 从 250 调成 300。试放尺寸、货架装箱、模块分页、连线桩标记避让、收口移动和最终复探会互相改变几何；继续堆常数补丁会让每次修复都成为下一次回归来源。建议按以下顺序开发。

**当前状态快照（以目检台账为准）**：同 pin 同网重复标记（C9）已经修复并复跑验证；但 req-08 仍出现标记侧位/压体和 place-only 计划摊页、空白率过高的问题。它们说明“电气网表已正确”与“页面可读、可交付”是两个独立目标，不能用一次 gate 结果替代布局验收。

#### 第 0 步：冻结范围和验收口径

先暂停新增布局特性，固定 3 个代表需求：小型 block-only、中型 freeform、最大多页需求。每个需求都在**全新工程**上跑，记录基线。

布局 Go 指标建议写死为：

| 指标 | v2 交付线 |
|---|---|
| 器件本体相交 | 0 |
| 引脚同点、错网、同 pin 重复载体 | 0 |
| 墨迹出可用带 | 0（oversize 必须显式标记） |
| 关键交付物 | SVG、网表、BOM、审计全部存在且可解析 |
| 普通页空白率 | 目标 20%至70%；末页或 oversize 单独标记 |
| `repack-fallback` | 支持域内 0；发生即进入失败分类，不静默继续 |
| 终态复探 | 所有移动、reseat、compact 后都必须再读一次 |

翼擦、文字重叠等暂时可做 warning，但必须计数，不能混入“完全通过”。

#### 第 1 步：建立唯一几何和网络真值

在布局阶段引入不可变的 `LayoutSnapshot`，至少包含：

- 每个器件的真实 body bbox、pin 坐标和真实 designator；
- 每条线段、netport、netflag、netlabel 的 ink bbox；
- pin 到 net、primitive id 到实例的映射；
- 页面 `sheetUsable`、图签 keepout 和 oversize 状态；
- snapshot 版本、读取时间和 EasyEDA/easyeda-agent 版本。

body、ink、electrical 三种口径必须分开。当前用 volume 估算分页、body 判断相交、再用盲退标记补救，容易出现“框不重叠但文字压体”或“有网但错网”。任何移动后都必须用真实回读刷新 snapshot，禁止继续使用 stale 坐标。

#### 第 2 步：把布局改成“两阶段、少回写”

建议流程固定为：

```text
清洁工程/页 → 单块试放量测 → 离线分页装箱
  → 一次性重放器件和块内连线 → 只做有限确定性修复
  → 终态回读 → 门禁/人工确认
```

装箱阶段只决定页和器件锚点，不再让 LLM 参与几何修复。布局约束按优先级排序：

1. 电气和器件本体不可相交；
2. 页面可用带、图签和模块 keepout；
3. 同模块亲和和关键接口方向；
4. 线长、可读性和空白率。

任何“为了填满页面”而移动器件的动作，都必须重新验证网络；如果无法证明保网，宁可保留空白并升级人工。

#### 第 3 步：优先解决重叠

- 试放必须覆盖 block-apply、place-only 和 freeform 三种通道，不能再因没有 upstream block 而退回旧流式布局。
- 分页前使用真实量测 bbox；估算框只能做初始上界，不能作为最终不相交证明。
- 为每个器件预留 pin 出线走廊和 netport 文字区，body keepout 与 ink keepout 分开计算。
- 移动对象优先选择小件或独立模块，限制单轮移动次数；移动前记录 pin-net，移动后逐脚比对。
- 对平台拒绝移动、回读为空、连接器异常，直接归类为环境失败，不触发 LLM 重规划。
- 增加“同网重复标记、脚有网但网名不对、线段中途并轨”三个独立硬检查，不能只查页级网名存在。

#### 第 4 步：解决页面空白率

空白率优化不能靠无限收紧间距，否则会重新制造翼擦和文字不可读。建议：

- 先按 module 和 band 分组，再做面积降序的装箱；
- 小型 place-only 器件与所属 freeform 模块绑定，禁止一件一页；
- 对同一模块设置“尽量同页、允许溢页”的软约束，并记录溢页原因；
- 只有单块确实超过可用带时才独占页，并显式标记 oversize；
- 每页计算真实 ink bbox 占用率，区分“空画布”与“被不可见文字/线段占用”；
- 页面少于最低占用率时，先尝试合并同模块小件，再尝试调整页序，不直接缩小所有间隙；
- `repack-fallback`、单页单模块和 >80% 空白应成为可查询的 warning/error 事件。

#### 第 5 步：给布局修复设置出口

布局修复每页最多执行固定次数，例如 3 次；每次必须满足“硬错误减少且没有新增电气错误”。出现以下任一情况立即停止：

- 连续两次 finding hash 不变；
- 本体错误未减少，只有翼擦数量变化；
- 移动后 pin-net diff 非空；
- 连接器或页面回读失败；
- 需要扩大到页外才能继续。

停止后的交付状态应是 `LAYOUT_REVIEW_REQUIRED`，而不是伪装成 PASS 或继续让 planner 重画整页。

#### 第 6 步：测试与发布顺序

1. 用固定几何夹具覆盖本体相交、重复标记、错网、侧位、出带和 place-only 分页。
2. fake 中显式模拟真实平台的拆不净、静默改 designator、移动不保网和回读 stale，避免 fake 过于干净。
3. 在全新 EasyEDA 工程上跑 3 个代表需求，保存截图、snapshot、audit 和最终网表 hash。
4. 连续三次真机复跑都满足硬指标后，才把布局算法标为 v2 可用；否则只发布为实验特性。
5. 布局稳定前冻结 v3 PCB、订单、更多多模态 datasheet 和大规模案例回写，避免继续扩大回归面。

#### 建议的三个开发批次

| 批次 | 时间盒 | 只做什么 | 退出条件 |
|---|---:|---|---|
| L0 取证批 | 1至2天 | 在全新工程复跑 req-08、req-07 和一个 block-only 需求；落 `LayoutSnapshot`、截图、audit；把平台故障与布局故障分栏 | 每个缺陷都有坐标、primitive、net 和复现命令；没有“未知原因”的 HALT |
| L1 几何批 | 3至5天 | 重写/收紧 packer 与终态硬检查，先解决本体相交、错网、重复载体、出带和 place-only 摊页 | 三个需求各连续 3 次真机复跑硬指标全零；缺陷减少而非只改变位置 |
| L2 交付批 | 3至5天 | 导出完整性、replay、preflight、失败分类和人工接管；把空白率、翼擦、文字可读作为可观测 warning | 交付文件 100% 可解析，任一外部异常都不会返回 PASS；安装和恢复步骤可由新用户执行 |

在 L2 通过前，不再新增布局常数、v3 模块或自动案例回写。若 L1 连续两批仍出现同类几何缺陷，应退回重做几何真值和流程边界，而不是继续扩大候选方向或提高迭代轮数。

推荐开发顺序是：范围和声明收敛，几何/网络真值，干净工程与适配器契约，重叠硬门禁，分页空白率，有限修复循环，真实回归和发布；之后才扩 datasheet、案例和 PCB。

## 7.开源社区、使用门槛、责任边界相关建议

知识库是持续运营成本。每个块都应有来源、许可证、pin/footprint 回读、电气字段、测试记录、版本和失效状态。`seeds` 与用户案例分库；用户案例默认隔离、脱敏、待审，不能因为 gate 通过就进入公共检索。

案例至少需要人工审核状态、模型和工具版本、最终网表 hash、finding、人工签核、适用范围和负例。支持撤回、降权、版本衰减和 holdout 检查。客户电路是否允许回写，必须显式 opt-in，不能从“成功运行”推断授权。

部署侧应提供一键 preflight、版本兼容矩阵、模型硬件档位、无密钥 dry-run、连接器诊断、日志清理和可恢复说明。没有本地模型和无网络验证前，不要使用“全离线”或“数据不出域”作为既成卖点。

开源工程还需要贡献模板、CODEOWNERS、SBOM、许可证审查、安全策略、上游版本契约测试和公开可复现 benchmark。上传的 PDF、需求文件和审计日志可能含敏感 IP，应默认不上传、不遥测。

责任声明必须同时出现在 UI、BOM、网表和报告中：

> PASS 仅表示已编码检查项通过，不表示电路功能、可靠性、安规、EMC、热设计或可制造性成立。

每次交付列出已检查项、未知项、引用出处、未覆盖功能、人工责任人，以及必须执行的 ERC/DRC、原理图复核、样机测试和必要仿真。禁止无人值守下单，禁止把 AI 输出直接当作工程签核。

## 8.最终总结结论

项目**值得推进，但必须重构定位和验收口径**：

- 从“通用智能原理图设计 Agent”收敛为“EasyEDA Pro 受控电路块原理图助手”；
- 从“机械校验保证正确”改为“机械校验缩减已知风险”；
- 从“案例自进化”改为“人工审核的数据资产建设”；
- 从“全链路自动化”改为“原理图闭环优先，PCB/订单仅作实验编排”。

当前项目是有工程含量的 alpha，不是 demo 玩具，也远不是企业级工具。布局卡点应被视为架构边界问题，而不是继续堆间距常数的局部 bug。先把真实几何、网络真值、分页和终态门禁做成可复验的小闭环，再扩展功能。

在扩大宣传或发布前，至少需要：支持域内 10 至 20 个真实项目；关键 pin/net/电气缺陷独立复核零漏报；交付物完整率 100%；真机重放一致；干净机器安装成功；布局本体相交、错网、重复载体和出带为零；若宣称私有部署，则在无网络、无云端 key、无云库依赖下完成证据。达不到这些条件，就继续以受控工程辅助工具推进，不要包装成自动设计平台。
